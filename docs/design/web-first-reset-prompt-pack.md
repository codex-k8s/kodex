# Промпты макетов web-first MatterCodex

Документ — самостоятельный пакет заданий для модели, генерирующей UI-макеты.
Каждый prompt содержит весь необходимый продуктовый контекст и может быть
скопирован отдельно. Объединять prompts перед генерацией не нужно.

Утверждённые результаты представлены самостоятельными HTML-макетами. Их
канонический состав, маршруты и способ локальной сборки зафиксированы в
[`mockups/index.md`](mockups/index.md). Raster-изображения не являются
источником реализации.

Промпты задают только продуктовый контекст, информационную архитектуру,
компоновку, тексты, состояния и требования доступности. Визуальный стиль
модель генерации определяет самостоятельно.

## Стабильные понятия

- MatterCodex — web-платформа управления ИИ-сотрудниками для любого бизнеса.
- `Проект` — единственное пользовательское название контейнера работы.
- `ИИ-сотрудник` — настраиваемый агент, выполняющий задачи.
- `Процесс` — workflow с одним или несколькими ИИ-сотрудниками.
- `Запуск` — конкретное исполнение агента или Процесса.
- `Помощник MatterCodex` — встроенный системный, неудаляемый и всегда готовый
  агент настройки платформы.
- Внешние системы, включая Mattermost, GitHub и Kubernetes, являются только
  необязательными интеграциями.

## Общие требования к генерации

- Генерировать самостоятельный статичный HTML-макет интерфейса, а не marketing page и не raster image. Макет должен открываться локально без backend и внешних ресурсов.
- Язык пользовательского интерфейса — русский.
- Не показывать raw UUID, digests, provider IDs, Kubernetes locators,
  Mattermost IDs, secret values, stack traces и raw provider responses.
- Не добавлять кнопки `Обновить`. Данные изменяются автоматически через
  realtime; допустимы только контекстные `Повторить` после конкретной ошибки и
  `Восстановить соединение` при offline.
- Основные действия приходят от сервера. Не показывать действие, отсутствующее
  в авторитетном `nextActions`.
- Статус передавать текстом и иконкой, не только декоративным признаком.
- На desktop сохранять видимый focus, логичный tab order, доступные названия
  icon-only controls и семантические headings.
- На mobile не уменьшать desktop canvas: таблицы превращать в списки, боковые
  панели — в последовательные секции или bottom sheet, интерактивные области
  делать удобными для касания.
- Для каждого экрана предусмотреть loading, empty, error, forbidden, offline,
  conflict, ongoing operation и ready. В основном HTML-макете показывать
  указанное ready-состояние; дополнительные HTML-состояния перечислены
  отдельно.

### Desktop prompt

```text
Создай статичный desktop UI-макет 1440×1024 для экрана первичной настройки web-приложения MatterCodex. MatterCodex — универсальная платформа управления ИИ-сотрудниками и выполняемыми ими процессами для продаж, поддержки, финансов, юридической работы, контента, операций и разработки. Пользователь уже успешно вошёл через корпоративную авторизацию. Это новая установка с одной организацией и без внешних интеграций. Не предполагается знание Mattermost, GitHub, Kubernetes или внутренних идентификаторов.

Покажи упрощённый application shell: слева знак и название MatterCodex без доступной рабочей навигации, сверху справа имя пользователя «Анна Волкова» и роль «Владелец». Основная область — onboarding с заголовком «Добро пожаловать в MatterCodex» и пояснением «Создайте первый Проект и ИИ-сотрудника. Интеграции можно подключить позже». Над содержимым покажи прогресс «Шаг 1 из 3 · Начало работы» и три этапа: «Цель», «Первый ИИ-сотрудник», «Первый запуск».

В центре размести крупный блок выбора пути. Основной вариант: «Начать с Помощником MatterCodex», описание «Расскажите, какую работу хотите организовать. Помощник предложит Проект и ИИ-сотрудника, а изменения будут применены только после вашего подтверждения», кнопка «Начать с помощником». Второй вариант: «Настроить вручную», описание «Создать Проект и ИИ-сотрудника через пошаговые формы», кнопка «Настроить вручную».

Рядом покажи фактическую готовность системного агента: «Помощник MatterCodex», метка «Системный · неудаляемый», статус «Готов к работе», пояснение «Действует от вашего имени и только в пределах ваших прав». Ниже короткий список гарантий: «Можно работать без интеграций», «Все изменения показываются до применения», «Действия сохраняются в аудите».

Пользователь должен сразу понять, что платформа готова, интеграции не обязательны и рекомендуемое действие — начать с помощником. Основное действие — «Начать с помощником». Вторичные данные — этапы onboarding и гарантии безопасности.

Empty-состояние неприменимо: это экран пустой установки. Loading показывается как подготовка bootstrap с текстом «Подготавливаем платформу…» без ложного статуса готовности. Ошибка показывает «Не удалось завершить первичную настройку», безопасный код и действие «Повторить подготовку». Ongoing operation блокирует повторный запуск и показывает текущий этап. Если помощник восстанавливается, заменить «Готов к работе» на «Восстанавливаем помощника» и временно предложить ручной путь. Недоступная интеграция не должна занимать отдельный блок: достаточно текста, что подключения выполняются позже.

Обеспечь логичный tab order: основной путь, ручной путь, меню пользователя. Visible focus обязателен. Не показывай secret fields, техническое состояние базы, UUID, cron, bot identity, Mattermost Team и кнопку обновления. Успех основного действия ведёт на полноразмерный экран Помощника MatterCodex.
```

Первой вертикальной секцией покажи системного агента: «Помощник MatterCodex», «Системный · неудаляемый», фактический статус «Готов к работе» и пояснение о действиях в пределах прав пользователя. ### Desktop prompt

```text
Создай статичный desktop UI-макет 1440×1024 полноразмерного workspace «Помощник MatterCodex». MatterCodex — web-платформа, где организации создают Проекты, ИИ-сотрудников, Процессы, запускают работу и принимают Human Gate. Помощник MatterCodex — единственный встроенный системный агент: он автоматически создан, неудаляем, всегда готов, сохраняет историю и выполняет конфигурационные изменения только через типизированные команды от имени проверенного пользователя. Он не имеет прямого доступа к PostgreSQL, Kubernetes или secret storage.

Application shell: слева глобальная навигация «Помощник MatterCodex» как активный выделенный пункт, затем «Главная», «Проекты», «Запуски», «Решения», «Интеграции», внизу доступное по правам «Администрирование». В header находятся project switcher со значением «Корпоративные продажи», глобальный поиск, индикатор «В сети», решения с badge «1», уведомления и меню пользователя «Анна Волкова».

Рабочая область состоит из трёх колонок. Левая внутренняя колонка — история диалогов: «Настройка отдела продаж» активна, ниже «Почему запуск остановился?» и «Подключение CRM»; кнопка «Новый диалог». Центральная колонка — диалог. В header: аватар, «Помощник MatterCodex», «Системный · неудаляемый», фактический статус «Готов». Покажи сообщение пользователя: «Создай проект для отдела продаж и агента, который будет анализировать материалы клиентов и готовить краткие рекомендации». Ответ помощника: «Я подготовил безопасный план. Внешние интеграции не требуются; их можно добавить позже».

Правая колонка — «План изменений». Покажи явный контекст «Проект: новый», две typed operations: «Создать Проект “Корпоративные продажи”» и «Создать ИИ-сотрудника “Аналитик продаж”». Для агента покажи назначение «Анализ материалов клиентов», instructions summary, capability «Работа с загруженными файлами», runtime «Стандартный», integrations «Нет». Ниже текст «Будет записано в аудит: Анна Волкова через Помощника MatterCodex». Основная кнопка «Применить изменения», вторичные «Изменить план» и «Отменить».

Внизу центральной колонки — многострочный composer с placeholder «Опишите задачу или настройку…», attach button с доступным названием, выбранный context chip «Корпоративные продажи» и кнопка «Отправить». Покажи подсказку «Enter — отправить, Shift+Enter — новая строка».

Пользователь должен понять: помощник системный, готов, действует в выбранном контексте, ничего не применил без подтверждения. Основное действие — «Применить изменения». Вторичные данные — история и объяснение выбранных настроек.

Empty показывает приветствие и примеры: «Создать Проект», «Подобрать роль агента», «Объяснить ошибку запуска». Error показывает безопасный отказ конкретной typed operation, не скрывая успешные действия. Conflict показывает, что исходная версия изменилась, и предлагает «Пересобрать план». Ongoing operation показывает последовательное выполнение операций и запрещает повторное применение. При recovery статус должен быть «Восстанавливаем помощника», composer временно недоступен, история остаётся читаемой. Если упомянута недоступная интеграция, пометь её «Недоступна» и предложи план без неё; не делай core assistant неготовым.

Tab order: история, диалог, composer, plan actions. При открытии action preview focus переходит на заголовок preview; после результата возвращается к сообщению. Не показывай prompt целиком, core prompt controls, UUID, secret values, raw tool payload, SQL, Kubernetes locators и кнопку обновления. Успешное действие даёт ссылки «Открыть Проект» и «Открыть ИИ-сотрудника».
```

Все controls доступны с клавиатуры и screen reader, touch targets не менее 44×44, focus после выполнения переходит к сообщению с результатом. Не показывай внутренние IDs, secret values, raw tool calls или кнопку обновления.
