# Пользовательские сценарии MatterCodex

## USR-ORG-001. Создать рабочую область

Владелец задает человекочитаемые имя, slug и описание. MatterCodex создает `Workspace` и команду Mattermost либо предлагает выбрать доступную существующую команду. Внутренние идентификаторы передаются скрыто.

## USR-AGT-001. Создать ИИ-сотрудника

Владелец выбирает `RoleDefinition`, имя и имя учетной записи бота, политику выбора учетной записи модели, интеграции, инструкции и профиль среды выполнения. Система проверяет учетную запись и показывает фактические полномочия.

## USR-CHAT-001. Поставить задачу с файлами

Пользователь пишет сообщение, прикладывает PDF и изображение. Агент получает манифест и локальные пути, анализирует материалы и возвращает Markdown-отчет и PNG в исходное обсуждение.

## USR-CHAT-002. Продолжить сессию

Пользователь пишет следующее сообщение тому же агенту. Если ход выполняется, сообщение ставится в очередь FIFO. После завершения текущего хода та же сессия продолжается со свежей конфигурацией среды выполнения.

## USR-RES-001. Принять законченный тип результата

Менеджер получает полный unit и параллельно запускает продуктовое, security и
архитектурное review на одном SHA. Исполнитель исправляет подтвержденные
замечания и системные аналоги, после чего все три направления проверяют новый
SHA. При отсутствии замечаний менеджер передает результат владельцу и ждёт
отдельного решения о слиянии.

## USR-PAR-001. Запустить несколько независимых волн

Корневой менеджер создает не более двух отдельных обсуждений дочерних
менеджеров, запускает их через MCP и отслеживает callbacks. Каждое обсуждение
соответствует одному unit и имеет собственный граф сессий и human gate.

## USR-INT-001. Подключить безопасную интеграцию

Администратор выбирает определение интеграции, вводит параметры подключения и ссылки на секреты, выполняет проверку и назначает возможности агентам. Значение секрета после сохранения не отображается.

## USR-APR-001. Подтвердить опасное действие

Агент запрашивает изменение внешней системы. Пользователь видит инициатора, инструмент, цель, риск, безопасные аргументы и срок действия. Решение не требует типизированной команды и может быть принято через несколько суток: pod агента за это время удаляется, а после решения исходная сессия Codex восстанавливается и получает результат инструмента.

## USR-SCH-001. Создать почасовую проверку заявок

Пользователь выбирает менеджера по продажам, пресет «каждый час», часовой пояс, почтовую интеграцию и промпт. При отсутствии заявок запуск остается только в аудите. При наличии заявок менеджер создает отдельные обсуждения и делегирует обработку.

## USR-SCH-002. Запустить ежедневного improver

`Improver` раз в сутки ищет merged PR без label `improved`, собирает их замечания и готовит один PR долговечных инструкций. После обработки он добавляет `improved` каждому просмотренному PR. При отсутствии полезных изменений новый PR не создаётся; собственное слияние не запускает improver рекурсивно.

## USR-NOGIT-001. Работать без репозитория

Рабочая область не имеет интеграции с Git. Пользователь загружает инструкции и рабочие материалы через UI или Mattermost. Агент получает материализованный `InstructionSet` и файлы, создает результат и возвращает его в обсуждение.

## USR-CFG-001. Изменить окружение следующего хода

Администратор меняет модель, глубину рассуждения, привязку MCP или право на
переменную окружения. Выполняющийся ход не прерывается. Следующий ход получает
новый `RuntimeRevision`, execution-scoped Pod, config, env и MCP client, а
session PVC и Codex thread binding сохраняются.

## USR-ACC-001. Балансировать новые сессии по учетным записям моделей

Роль использует пул учетных записей. При создании новой сессии планировщик выбирает разрешенную авторизованную учетную запись с учетом свежести данных и доступных лимитов. Возобновление всегда использует учетную запись, закрепленную за сессией.

## USR-OPS-001. Восстановить платформу

Оператор разворачивает чистую промышленную инсталляцию, восстанавливает PostgreSQL PITR, файлы S3 и конфигурацию Kubernetes, затем выполняет проверяемый сценарий восстановления.
