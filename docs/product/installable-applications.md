# Устанавливаемые приложения и источники каталога

## Статус решения

Документ утверждает целевую продуктовую модель расширения Kodex. Реализация
каталога, установки и исполнения пакетов относится к `POST-MVP`: она не входит
в демонстрационный профиль, не является зависимостью core readiness и не
расширяет текущий MVP.

Kodex не встраивает в ядро отдельные магазины для разработки, продаж,
бухгалтерии или другой предметной области. Любое устанавливаемое расширение
описывается одной универсальной моделью пакета приложения.

## Пользовательские понятия

- `Пакет приложения` (`ApplicationPackage`) — каталоговая сущность расширения с
  устойчивой идентичностью, издателем и доступными версиями.
- `Версия пакета` (`PackageVersion`) — неизменяемая версия manifest и
  артефактов, закреплённая за точным источником и digest.
- `Manifest` — декларация возможностей, разрешений, секретов, runtime-требований
  и допустимых областей установки без значений секретов.
- `Источник каталога` (`PackageSource`) — внутренний, внешний или
  пользовательский источник метаданных и версий пакетов.
- `Установка` (`PackageInstallation`) — выбранная версия пакета и её состояние
  в конкретной области платформы.
- `Capability` — типизированная возможность, которую пакет предоставляет
  пользователю, агенту, Процессу или платформе.

Термин `plugin` допустим в интерфейсе как привычное название расширения, но не
создаёт отдельную модель жизненного цикла. Интеграционный adapter, пакет
руководств, дополнительный канал, отраслевое приложение и средство
развёртывания являются вариантами одного `ApplicationPackage` с разными
capabilities.

## Что описывает manifest

Manifest версии содержит как минимум:

| Раздел               | Назначение                                                                          |
| -------------------- | ----------------------------------------------------------------------------------- |
| Идентичность         | Устойчивый package key, издатель, версия, лицензия и локализованные metadata.       |
| Источник             | Тип источника, точная revision и digest manifest/артефактов.                        |
| Capabilities         | Закрытый набор предоставляемых возможностей и их типизированные интерфейсы.         |
| Permissions          | Минимальные platform actions, внешние эффекты и классы риска, необходимые пакету.   |
| Secret schema        | Имена, типы, обязательность и пользовательские подсказки без значений секретов.     |
| Runtime requirements | Режим исполнения, immutable images, ресурсы, health, сеть, volumes и совместимость. |
| Installation scopes  | Допустимые области установки и правила singleton/multiple instances.                |
| Dependencies         | Совместимые версии платформы и других пакетов без неявного автодобавления.          |
| Lifecycle            | Условия install, configure, activate, upgrade, suspend и uninstall.                 |

Категория пакета используется для поиска и представления в UI, но не является
источником полномочий. Реальное поведение задают проверенные capability,
permissions и runtime requirements.

## Области установки

Manifest объявляет только допустимые области. Конкретную область выбирает
пользователь, а сервер проверяет его полномочия:

- `platform` — вся инсталляция; только для администратора платформы;
- `organization` — одна Organization;
- `project` — один Проект;
- `agent` — один ИИ-сотрудник внутри разрешённого Проекта.

Установка в более широкую область не выдаёт пакету неограниченный доступ ко
всем вложенным объектам. Каждая capability получает отдельные grants в
фактической области использования.

## Источники каталога

### Внутренний источник

Поддерживаемый владельцем инсталляции проверенный каталог. Он может содержать
рекомендованные бесплатные или коммерческие пакеты, но не является обязательным
публичным marketplace и не участвует в core readiness.

### Внешний магазин

Подключённый магазин поставщика или другой организации. Kodex синхронизирует
его доступные metadata и версии в локальный каталог. Пользовательские чтения не
зависят от доступности магазина в реальном времени.

### Пользовательский источник

Добавленный администратором прямой источник пакета: например, приватный OCI
artifact или репозиторий с зафиксированной revision. Такой источник проходит те
же проверки manifest, digest, совместимости и разрешений, что и магазин.

Источник определяет происхождение пакета, но не доверие к нему. Уровень доверия
вычисляется локальной политикой проверки. Отключение источника не удаляет
автоматически установку и не меняет уже зафиксированную версию без явного
действия пользователя.

## Пользовательский жизненный цикл

1. Администратор подключает источник или выбирает уже доступный локальный
   каталог.
2. Kodex синхронизирует metadata и проверяет точную версию пакета.
3. Пользователь выбирает область установки и видит capabilities, permissions,
   требуемые secrets, ресурсы и риски до подтверждения.
4. Пользователь заполняет необходимые секреты через защищённую форму. Значения
   не попадают в manifest или каталог.
5. Сервер проверяет полномочия и создаёт неизменяемый план установки.
6. После Human Gate, если он требуется политикой риска, Kodex материализует
   установку и показывает её фактическое состояние.
7. Upgrade, suspend и uninstall являются отдельными наблюдаемыми операциями с
   аудитом, recovery и понятным результатом.

Установка пакета не означает автоматическую выдачу всех заявленных разрешений.
Пользователь подтверждает exact набор, а Kodex может закрыто отклонить
capability, запрещённую политикой инсталляции.

## Универсальные примеры

- отраслевое приложение для подготовки и согласования документов;
- adapter к CRM, почте, 1С или внешнему хранилищу;
- канал входящих обращений и исходящих уведомлений;
- пакет инструкций и шаблонов для ИИ-сотрудников без исполняемого runtime;
- приложение для развёртывания workloads в отдельном nested cluster.

Последний пример не превращает Kubernetes или nested cluster в специализацию
ядра. Пакет объявляет capability развёртывания, необходимые манифесты/образы и
типизированное подключение к целевой среде. Доступ, Human Gate и аудит остаются
в общих границах Kodex.

### Инструкции и шаблоны ролей

Пакет может доставлять руководящие документы, шаблоны инструкций, ролей и
Процессов без исполняемого runtime. Установка делает их доступными для импорта в
выбранной области и сохраняет источник и версию. Она не превращает проектную
документацию в глобальное руководство и не изменяет уже опубликованного
ИИ-сотрудника или Процесс при обновлении пакета. Пользователь явно создаёт новую
draft-версию и публикует её обычным lifecycle Kodex.

## Ограничения целевой модели

- Публичный marketplace не является единственным или обязательным источником.
- Непроверенный пакет нельзя активировать только потому, что он виден в
  каталоге.
- Manifest не содержит значения секретов и не может сам выдать себе grant.
- Пакет не получает прямой доступ к БД других доменов или к secret storage.
- Магазин не является источником состояния локальной установки.
- Установка не исполняет произвольный shell с полномочиями узла.
- Пакет руководств или шаблонов не требует runtime только ради доставки файлов.
- Встроенные seed-объекты MVP не обязаны быть переупакованы до реализации
  POST-MVP каталога.

## Ручная проверка будущей реализации

После появления package unit владелец проверяет три независимых сценария:

1. установка проверенного пакета из внутреннего источника;
2. синхронизация и установка версии из внешнего магазина при последующей
   недоступности магазина;
3. установка пользовательского пакета, который предоставляет capability
   развёртывания в nested cluster, с exact permissions, Human Gate и аудитом.
