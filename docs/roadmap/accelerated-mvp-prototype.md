# Форсированный план прототипа MVP до 27 июля 2026 года

## Решение владельца

До конца 27 июля 2026 года проект работает в режиме
`prototype-accelerated`. Цель — получить работающий сквозной прототип по
утверждённой продуктовой документации, допускающий известный оформленный долг.
Следующие две недели предназначены для hardening, UX-полировки и закрытия
backlog, а не для первоначального построения продукта.

## Критерий прототипа

К 27 июля владелец должен иметь возможность на действующем инстансе:

1. создать или использовать workspace, комнату и агентов без внутренних ID;
2. запустить долговечную сессию, продолжить её после пересоздания pod и увидеть
   корректный статус;
3. назначить новую конфигурацию, account и integrations следующему turn;
4. передать входной файл агенту и получить файл или изображение в ответ;
5. запустить дочернего агента в новом треде и получить callback;
6. выполнить минимум одну управляемую integration capability с human approval;
7. создать и немедленно выполнить минимум одно расписание;
8. управлять основными сущностями через рабочий UI или Mattermost-формы;
9. выполнить сквозной smoke и увидеть известные ограничения в backlog.

Полная HA, все интеграции, исчерпывающий Control Center, промышленное backup
и публичный release не входят в критерий 27 июля.

## Шесть параллельных слотов

Директор держит до шести активных manager-волн:

1. **Foundation:** завершить PR-2, PR-3 и PR-4 Wave 1 в их обязательной
   последовательности; подготовка следующего среза допускается параллельно.
2. **Runtime:** минимальный `RuntimeRevision`, account binding, архив и
   восстановление сессии, пересоздание pod с актуальной конфигурацией.
3. **Artifacts:** входные вложения, workspace manifest и исходящая публикация
   файлов и изображений.
4. **Universal model:** совместимый вертикальный срез Workspace/Room/Agent и
   `InstructionSet` без обязательного Git-репозитория.
5. **Integrations:** минимальные Connection/Capability/Grant, MCP gateway и
   один сквозной approval для опасного действия.
6. **Control and automation:** минимальный Control Center/Mattermost UX,
   playbook callback и одно расписание с ручным запуском и историей.

Освободившийся слот немедленно занимает следующий готовый срез Wave 6-9.
В каждой волне одновременно существует не более одного implementation PR на
одну область данных.

## Ритм одного PR

- разработка и автоматические проверки;
- один параллельный reviewer pass и один security pass;
- один цикл исправления blocker;
- проверка менеджером и merge;
- post-merge reviewer/security создают backlog Issues;
- owner attention только для нового решения, опасного deploy или blocker.

Ориентир — PR длительностью до одного рабочего дня. Если результат не помещается,
менеджер режет его по вертикальным сценариям, а не на слои без пользовательской
ценности.

## Контрольные даты

- **21 июля:** переключение процесса и ресурсов кластера, запуск шести слотов.
- **22–23 июля:** PR-2/PR-3 и первые Runtime/Artifacts/Model срезы.
- **24–25 июля:** PR-4, integrations, control/automation и сборка сквозного пути.
- **26 июля:** интеграция, миграции, deployment и полный E2E.
- **27 июля:** исправление blocker, повторный E2E и фиксация prototype tag.
- **28 июля – 10 августа:** hardening, backlog, UX и эксплуатационные проверки.

## Ограничения скорости

- `mvp-blocker` останавливает только затронутую волну;
- `mvp-follow-up` не блокирует независимую разработку;
- один большой PR, общий для нескольких слотов, запрещён;
- зависимости по схеме и владению данными не обходятся ради календаря;
- отсутствие CI, непроверенный deploy и пропущенный E2E фиксируются честно.
