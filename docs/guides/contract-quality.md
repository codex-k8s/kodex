# Качество API и событийных контрактов

## OpenAPI

- Исходный YAML- или JSON-контракт хранится в `contracts/openapi`.
- Стабильные идентификаторы операций и переиспользуемые схемы и ошибки.
- Пагинация, фильтрация и сортировка задаются явно.
- Секретные поля только для записи не возвращаются API чтения.
- Нарушение совместимости проверяется по активному профилю `GOV-DOC-003`;
  отсутствие отложенной тяжёлой проверки само по себе не является замечанием.
- Серверные и клиентские типы генерируются; ручные DTO допустимы только на
  границе адаптера с явным преобразованием и применимой быстрой проверкой.

## AsyncAPI

Каждый конверт команды или события содержит:

- `event_id`;
- `event_type` и версию;
- `occurred_at`;
- `organization_id`;
- `correlation_id`;
- `causation_id`;
- `idempotency_key`;
- типизированную полезную нагрузку.

Обработчик обязан выдерживать повторную доставку и неизвестные необязательные поля.

Каждый `server`, `channel`, `operation`, `message`, `schema` и `enum` имеет
полезное русское описание. Для каждой операции effectful consumer явно указаны
workload/owner, subject/stream, durable inbox/cursor, эффект, семантика
duplicate/stale/gap, чтение/повторное присоединение и readiness. Stateless
WebSocket fan-out без локального эффекта явно указывает отсутствие inbox,
авторитетный event store/cursor, периодическую сверку и автоматический
catch-up/resync. Реестр
перечисляет consumer только при наличии всех этих частей; профиль gRPC
producer не подменяет операцию AsyncAPI.

Ссылочное событие содержит точные aggregate ID+version и защищённый путь чтения
закреплённой версии для каждого consumer либо полный безопасный неизменяемый
снимок. `staging` и `production` servers описываются раздельно с точными
TLS/credential профилями. Исходный YAML проходит воспроизводимую генерацию;
при недоступной семантической CLI честно фиксируется только выполненный разбор
YAML, а не CI/PASS инструмента.

## Protobuf/gRPC

- Используется только при обоснованном внутреннем контракте.
- Пакет и версия отражены в пути и пространстве имен.
- Номера полей не переиспользуются; удаленные поля резервируются.
- Сроки выполнения и преобразование состояний документированы.
- Проверки и генерация Buf выполняются по активному профилю `GOV-DOC-003`.
  Локальный запуск относится к точному SHA и не называется CI; отсутствие
  GitHub check не является успешной проверкой.
- Каждый `service`, RPC, `message`, field, `enum` и каждое enum value имеет
  содержательный русский комментарий в исходнике. Комментарий повторяет не
  имя, а источник полномочий, семантику owner/tenant, idempotency/OCC,
  жизненный цикл и terminal/hidden поведение там, где они существенны.
- Закрытые enum документируют смысл каждого значения, включая unknown/zero;
  удалённые values/fields резервируются и не переиспользуются.
- Поля запроса `actor`, `owner`, tenant, parent, target и version не
  объявляются источником полномочий; комментарий указывает назначаемый сервером
  источник.
- RPC защищённого жизненного цикла покрывают все применимые create/claim/renew/
  complete/cancel/delete/retry/expiry/continuation paths по `GUIDE-DOC-006`.
- Исходный Proto является единственным источником. Сгенерированный
  Go/TypeScript не редактируется вручную, а повторный `buf generate` на чистом
  исходнике даёт нулевой diff и сохраняет комментарии в сгенерированном API.

## Сквозная согласованность

Review контракта составляет карту `источник требования -> actor/authority ->
external endpoint/producer -> gateway/client -> RPC/operation -> data owner ->
state/event -> consumer/readback`. Совпадение имён не доказывает совпадение
типов, версий, полномочий, жизненного цикла и ошибок.

Машиночитаемые реестры error/method/authority охватывают каждый RPC и
используют один закрытый набор. Неизвестная комбинация reason/code/retryable,
метод без профиля permission или consumer без operation закрыто отклоняются.
Документация и реестр проверяются после codegen, а не только по исходному
файлу.

## Инструменты MCP

- Имя инструмента стабильно и версионируется через `IntegrationDefinition`.
- Вход и выход описаны JSON Schema.
- Риск, необходимое право, идемпотентность и правила согласования обязательны.
- Результат инструмента структурирован; человекочитаемый текст не является единственным каналом состояния.

## Проверка результата

Контрактный результат проходит отдельные проверки: корректность домена, совместимость, безопасность и персональные данные, идемпотентность и повторы, удобство сгенерированных клиентов.
