# Граница текущей приёмки

Решение владельца 30.10.2026: ближайшая цель — ограниченный интеграционный
пилот за пять часов, сотрудники/MCP/GitHub/файлы/согласования. Полный
автоматический PDLC и полный QA отложены. Этот документ фиксирует открытые
обязательства; он не подтверждает их выполнение и готовность production.

Эпик [#1830](https://github.com/codex-k8s/kodex/issues/1830), общий Draft PR
[#1970](https://github.com/codex-k8s/kodex/pull/1970). Исходная контрольная
точка пилота — `38be75a8c6e6bddbf8b0fa3d3169d4f781ad72ab`.
Этот код реально обслуживают control-plane и staff-control-center; остальные
компоненты имеют отдельные закреплённые версии. Применимые backend проверки
выполнены на 7e506c8a с доказанно идентичными backend inputs, frontend и
render/install contract — на 38be75a8. Единый полный immutable release и чистая
установка на другом сервере не приняты. Подробная карта, результаты и возврат:
[инструкция пилота](integration-pilot-20261030.md).

## Сохранённая диагностика recovery

Основной процесс «Журнал обращений» остановлен после подтверждённых отказов:
первый completion исчерпал RPC-бюджет; после исправления #1927 business attempt2
завершилась RESULT_INVALID, поскольку отсутствовали FILE/COMMENT proofs.
Опубликованный workflow также не включает comment.list в required capabilities,
хотя grant есть в карточке сотрудника. Карточка grant не доказывает его наличие
в frozen RuntimeRevision. В следующей конфигурации это READ-право нужно задать
явно; текущую опубликованную версию посреди запуска не менять.

[Бизнес-запуск](https://platform.kodex.works/projects/prj_NAKh_NrtthS8M2rg8CtWUMEM/runs/run_lT1SyuLzOWz_CEjlQcnm0Ydl)
штатно отменён через Chrome UI: CANCELLED,18 точных CLEAN revisions скачаны с
совпадающими хешами, активных узлов нет. Это сохранение опубликованных результатов,
а не успешное завершение PDLC.

Кандидат compact recovery manifests прошёл unit, но не native acceptance за три
попытки. Последний отказ: старый selector занял 1415ms, исторический selector
отменён через 3584ms в общем 5s бюджете. Код не опубликован и не развёрнут;
diff, исходники, hashes и stash сохранены приватно. Повтор этого пути остановлен
по правилу владельца. Следующее исследование — ограниченный выбор типа источника
до тяжёлого selector либо отдельная закрытая read operation, без увеличения
timeout и ослабления authority. Подробности:
[диагностика #1972](https://github.com/codex-k8s/kodex/issues/1972#issuecomment-6513226498).

## Что подтвердил ограниченный пилот

На CP/PWA 38be75a8 два успешных документальных процесса аналитик → QA на одной
опубликованной версии, включая после адресного restart. Сервер принял обязательные
ARTIFACT, передал файл QA и выполнил downstream без модельного хода менеджера;
в одном процессе QA физически продолжился через CONTINUES. Изолированные Gates
APPROVED через настоящий Chrome UI,6 и 8CLEAN файлов соответственно доступны.
Эти результаты не заменяют несколько успешных полных GITHUB_PDLC прогонов.

Отдельный продуктовый рецензент через MCP создал настоящий COMMENT review,
нашёл конкретный пробел памятки и сохранил 4CLEAN файла. Прямые host-операции
не использовались для написания приложения или публикации этого review.
Неблокирующее ограничение [#1976](https://github.com/codex-k8s/kodex/issues/1976):
URL review теряется в native output projection; запись и ID/head/body подтверждены,
ссылку host получил отдельным разрешённым GitHub readback. Файлы сотрудника с
честным UNKNOWN URL не переписывались задним числом.

Во время отдельного процесса deadline шага истёк раньше собственного срока Gate.
Это корректный RUNTIME_TIMEOUT/CANCELLED по действующей политике #1869, а не
новый дефект: ожидание владельца не останавливает часы исполнения. Полная
матрица гонок и бизнесовые merge/deploy Gates остаются в следующей приёмке.

## Условия возобновления полного PDLC

1. Закрепить отдельную контрольную точку после интеграционного пилота, перечитать
   текущие Issues и actual serving/schema; не переносить исторические статусы.
2. Сначала закрыть потерю рабочих файлов и устойчивое восстановление, затем
   recovery handoff, автоматические доработки и отдельный выпуск SRE.
3. Использовать новую явно опубликованную конфигурацию процесса с необходимыми
   READ-grants, корректными обязательными результатами и коротким понятным
   проектом. Код приложения выполняют сотрудники, хост диагностирует платформу.
4. Повторить полную цепочку с несколькими успешными прогонами, затем восстановление
   backup и квалификацию штатного immutable cohort на одном чистом SHA.

Для пилота эти задачи остаются ограничениями. Нельзя выдавать MVP/full PDLC,
автоматический выпуск, безопасный crash-resume или disaster recovery за готовые.
Production и итоговое слияние QA PR требуют отдельного решения владельца.
Значения credentials, cookies, kubeconfig, Secret и DSN в документ не включены.
