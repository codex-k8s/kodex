# Защита служебного контекста удаления проекта

Задача [#1916](https://github.com/codex-k8s/kodex/issues/1916),
эпик [#1830](https://github.com/codex-k8s/kodex/issues/1830).

## Дефект и граница исправления

Default privileges владельца выдавали runtime запись в новые таблицы.
Создание `project_purge_context` и `project_purge_targets` отзывает права
PUBLIC, но сохраняет эту отдельную выдачу. Поэтому прямой SQL от runtime
может подделать служебный контекст и разрешение удаления защищённых строк.
Внешний HTTP-путь эксплуатации этим заключением не утверждается.

Миграция `20261026000200_project_purge_authority_acl.sql` отзывает
INSERT, UPDATE, DELETE, TRUNCATE, REFERENCES и TRIGGER у runtime на обеих
таблицах. SELECT сохраняется для существующих INVOKER guards. Сигнатуры,
тела функций, бизнес-состояния, граф purge и контракты API не меняются.
Правка не требует установки незавершённого серверного DAG.

| Действие | Источник полномочий и результат |
| --- | --- |
| Чтение контекста guard | Прежняя runtime identity, только SELECT; без нового события |
| Прямая запись runtime | PostgreSQL отклоняет запись до изменения состояния; без события |
| Штатный purge | Прежняя owner-функция и точная проектная область; прежняя атомарная транзакция и события |
| Миграция | Штатный migrator под owner-role, одна Goose-транзакция с отзывом ACL; без бизнес-события |
| Неизвестный исход Job | Авторитетное inspect того же плана; повторное создание Job запрещено |
| Возврат приложения | Предыдущий образ CP после завершения Job; отозванные права не возвращаются |

## Воспроизведение и регрессионная проверка

На отдельном PostgreSQL запустить публичную точку входа:

```sh
bash scripts/tests/control-plane-postgres-test.sh '^(TestProjectPurgeAuthorityComponent|TestProjectPurgeAuthorityMigrationProofComponent|TestOwnerGateExpiryMigrationProofComponent)$'
node --test --test-concurrency=2 tools/release/control-plane-migration.test.mjs tools/release/control-plane-immutable-migration.test.mjs
```

Первая проверка использует настоящий runtime LOGIN: SELECT разрешён,
восемь попыток INSERT/UPDATE/DELETE/TRUNCATE отклонены с insufficient_privilege.
REFERENCES и TRIGGER проверяются через эффективные ACL, без отдельного DDL.
Проверка release SQL намеренно возвращает опасные table, column и PUBLIC grants,
ослабленную функцию авторизации и альтернативную роль записи, доступную через
SET ROLE при INHERIT FALSE, только в отдельных одноразовых БД. Дополнительный
fixture проверяет ADMIN OPTION при SET FALSE: право изменить членство
должно закрыто отклоняться до получения разрешения на переключение роли.
Каждое отклонение обязано отразиться в соответствующем отрицательном поле.
Эти fixtures не выполняются в staging и не создают состояния через живую БД.

Проверки bundle и срока Human Gate сохраняют точные проверки схемы и функции;
новая версия Goose разрешается только явно выбранной проверкой новой схемы.
Успех тестового CLI с подставленным kubectl не заменяет PostgreSQL и live readback.

## Доставка и ручная проверка

Использовать существующий `tools/release/control-plane-migration.mjs` с
`--profile project-purge-authority`: plan → check → stop → apply → inspect → resume.
План привязывает чистый SHA, immutable image и публикацию, UID кластера,
namespace, CP и PostgreSQL, а также хеши SQL. Последняя миграция образа должна
быть ровно `20261026000200`; предыдущая версия БД — `20261026000100`.
Сначала проверяется отсутствие активных запусков, согласований и фоновых работ.
CP останавливается штатным stop/join, затем исполняется единственная Job.

Read-only postcondition проверяет обе таблицы, владельца, всех наследников
runtime и хотя бы один LOGIN, также достижимые через SET ROLE роли,
отсутствие ADMIN OPTION у runtime и доступных ему ролей, эффективных table/column write и
grant option, отсутствие PUBLIC grants, необходимое чтение и owner-запись,
пустоту служебных таблиц и точное определение функции авторизации.
Отрицательное поле запрещает объявлять миграцию успешной. Произвольные прямые
grants другим ролям не удаляются автоматически: такой drift требует отдельного
адресного исправления. Диагностика не выдаёт имён LOGIN или содержимого строк.

После inspect и resume проверить две Ready-реплики прежнего CP, чтение истории
через UI, сохранение артефактов и штатное удаление отдельного QA-проекта.
Проверить Console и относящиеся к сценарию Network, затем повторить чтение
после адресного рестарта. Live-проверка и сборка immutable-образа фиксируются
отдельно с точным SHA; этот документ сам по себе не является их доказательством.

## Возврат

Миграция forward-only: Down закрыто отклоняется. Возврат версии приложения
сохраняет ограниченные ACL; возвращать опасные права ради rollback нельзя.
При тайм-ауте сначала inspect исходного плана и Job. Не создавать новую Job
или idempotency key, пока исход прежней операции неизвестен. Resume использует
сохранённый образ и число реплик после подтверждения завершения migrator.
Секреты, cookies, DSN и значения конфигураций в доказательства не включаются.
