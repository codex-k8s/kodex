# Совместная отладка прототипа

Область: локальный `trusted-cluster`, единственный клон
`/home/s/projects/matter-codex`, эпик #1763 и единый PR #1781. Это рабочий
журнал, а не доказательство приёмки. Слияние PR — только по отдельной команде
владельца; staging и production не затрагиваются.

## Краткий план

1. Владелец вручную проходит один шаг в Control Center и сообщает экран,
   действие, ожидаемый и фактический результат, безопасный фрагмент консоли или
   снимок экрана. Секреты, токены и персональные данные в журнал не переносятся.
2. Исполнитель сверяет время и шаг с логами **локального** кластера, определяет
   корневую причину и фиксирует в таблице ниже только подтверждённый дефект.
3. Исполнитель исправляет код в том же клоне, ветке и PR #1781; миграции — только
   новые forward-only, штатным repo-owned путём. Фикстуры без команды владельца
   не пересоздаются.
4. После адресных проверок исполнитель подтверждает, какой исходник виден Pod,
   что приложение подхватило изменение через Air/Vite, и сообщает точный commit
   или незакоммиченный diff. Сборка или deploy образа допускаются только когда
   действительно изменилось содержимое образа.
5. Исполнитель проверяет исправление в уже открытой вкладке локального Control
   Center через Chrome DevTools: дождаться Air/Vite, перезагрузить без кэша,
   проверить console, нужный сценарий, screenshot и network 4xx/5xx. При
   ошибочном запросе безопасно изучить request/response и повторить цикл.
   Владелец затем проверяет тот же шаг вручную; до его ответа запись остаётся
   `ОЖИДАЕТ ПОВТОРА` даже при успешной автоматической проверке.

По решению владельца исходники остаются подключёнными напрямую через read-only
`hostPath`: host и Pod видят один клон. PVC для исходников не создаётся. Кэш
сборки остаётся вне Git и не является источником кода.

С 2026-09-25 приоритет — быстрый цикл на живом локальном стенде. По новому
решению владельца повторные широкие прогоны на одноразовой PostgreSQL в этом
цикле не требуются: выполняются только проверки, нужные для конкретной правки.
Существующие локальные данные и фикстуры не пересоздаются. В Chrome DevTools
используется только уже открытая вкладка приложения; временную вкладку макета
нужно закрыть сразу после сравнения. Ориентир desktop 1920×1080; мобильная
доводка отложена. Главный экран перерабатывается по
`docs/design/mvp-redesign/home-a-attention-center-desktop.html`, остальные
экраны — по соответствующим макетам. Если существенное отличие может быть
ранее согласованным, исполнитель даёт владельцу варианты, не меняя его молча.

## План кодовой готовности общего сценария

До приглашения владельца на визуальную приёмку помощник должен закрыть в одном
чате цепочку `проект → сотрудник → образ → окружение → значения и привязки
секретов → интеграции и разрешения → запуск`, а также изменение существующих
объектов. Ручные формы остаются единственным UI-контрактом: помощник готовит
типизированные предложения, форма открывается с безопасными заполненными
полями, владелец меняет их и подтверждает специализированную команду. Значения
секретов вводятся только в защищённую форму и не попадают в модель или историю.

Промежуточный кодовый этап `76e04157`:
повторное использование защищённой формы секрета в чате с ограниченным
возвратом после SSO; редакторы образа и окружения подключаются к соседней
панели помощника без закрытия чата. Адресные типовые и unit-проверки — PASS;
визуальная проверка и полный сценарий — NOT RUN. Это не отмашка на приёмку.

Следующий пакет расширяет `CREATE_RUNTIME_ENVIRONMENT_DRAFT` только публичными
переменными среды и ссылками на уже созданные секреты текущего проекта.
Значения новых секретов остаются вне модели и плана; сервер принимает только
закрытую структуру, а владение Secret проверяется при валидации/публикации
черновика. Изменение `PREPARE_RUNTIME_ENVIRONMENT_REVISION` по-прежнему не
меняет эти поля. Адресные Go unit/vet и runtimecontract — PASS; полный
PostgreSQL component и визуальная проверка — NOT RUN.

Пакет `00e161ba` расширил редактирование ревизии окружения теми же
двумя типизированными списками и выводит оба списка в явную форму плана до
применения. Списки заменяются целиком, поэтому без полного авторитетного
снимка помощник не должен их угадывать; владелец может проверить и изменить
их в форме. Сервер сохраняет инструменты и политику из текущей ревизии,
привязывает изменение к версии и повторно проверяет Secret при публикации.
Адресные Go unit/vet, frontend typecheck/lint/build и связанный PostgreSQL
component на отдельной одноразовой БД — PASS на дереве `00e161ba`;
browser — NOT RUN. Попытка запустить только внутренний подтест
component — FAIL из-за отсутствия образа, создаваемого предыдущим подтестом;
полный `TestBootstrapComponent` с этой фикстурой затем завершился PASS. Прямой
read-only source mount подтверждён совпадением SHA host/Pod, Air повторно
собрал control-plane и runtime-controller, Vite отдаёт новый модуль. Это не
доказательство сквозной пользовательской приёмки.

Следующее изменение выносит строки публичных переменных и Secret binding в
один Vue-компонент, используемый и штатным редактором окружения, и формой
плана помощника. Так проектный picker и предупреждение о запрете значения
секрета имеют один UI-контракт. Адресные unit, typecheck, ESLint и production
build — PASS на незакоммиченном diff после `00e161ba`; build сохраняет
предупреждение о чанке >500 KiB. Browser/визуальная проверка — NOT RUN.

Форма проекта также выделена из обычной страницы в общий компонент для
ручного создания и предпросмотра плана помощника. Поля, ограничения
`120/1000` символов и обязательность теперь одинаковы; каталог инструментов
использует те же лимиты, а план не применяется с неполной формой. Адресные
frontend typecheck, lint, unit и build, а также runtime-controller Go test/vet
— PASS на незакоммиченном diff после `f96cdeab`; browser — NOT RUN.

Форма создания сотрудника также выделена в общий компонент: имя, назначение,
роль, инструкции и выбор готового runtime совпадают в обычном экране и плане
помощника. Помощник не назначает runtime без выбора владельца: неизвестная или
неготовая ссылка закрыто блокирует применение. Дополнительные возможности
остаются отдельными явными флажками плана; лимиты каталога инструментов
синхронизированы с формой. Адресные frontend unit/typecheck/lint/build и
runtime-controller unit/vet — PASS на незакоммиченном diff после `890e378e`;
визуальная проверка — NOT RUN.

Кодовый сценарий подсказки секрета: пользователь просит окружение с секретом →
помощник передаёт в закрытой схеме плана только имя, описание, тип и подсказку
об источнике будущего значения → control-plane сохраняет и проверяет эти
неисполняемые метаданные внутри project-scoped плана → UI предлагает открыть
существующую защищённую форму секрета, заполненную только метаданными →
владелец лично вводит значение и подтверждает создание черновика → штатный
gateway и owner control-plane проверяют сессию, проект и idempotency,
возвращают авторитетный draft/readback. Значение не попадает в план, модель,
чат или журнал; создание секрета не меняет план и не означает публикации
окружения. После создания владелец выбирает точную ссылку на секрет в форме
окружения, проверяет и отдельно публикует его. Ошибка или отмена формы не
создаёт привязку автоматически; повтор пользуется контрактом защищённой формы.
Новая ревизия системного промпта `v26` явно запрещает значение в подсказке и
требует вернуться к привязке только после авторитетного создания Secret.
Адресные Go unit/vet, frontend unit/typecheck/lint/build — PASS на
незакоммиченном diff после `3f535087`; browser и переход через fresh-auth с
сохранением метаданных подсказки — NOT RUN. Отмена формы не подтверждена в UI.

Поля публичной конфигурации подключения теперь один компонент на обычном
экране и в плане помощника: варианты выбора, HTTPS URL, числовые границы,
списки и ошибки показываются одинаково. Credential остаётся отдельным
защищённым шагом и не включён в этот компонент. Адресные frontend unit,
typecheck, ESLint и build — PASS на незакоммиченном diff после `1d41994f`;
визуальная проверка — NOT RUN. Это ещё не общая форма полного подключения.

Основные поля полного редактора процесса (название, назначение, координатор,
таймаут, критерий завершения, параллелизм) вынесены в общий компонент для
штатной страницы и формы плана помощника. Выбор координатора остаётся
ограниченным текущим проектом; этапы, входные поля и полномочия процесса пока
отображаются прежними специализированными контролами и требуют дальнейшего
сближения. Адресные frontend typecheck, ESLint, unit и build — PASS на
незакоммиченном diff после `a656e787`; визуальная проверка — NOT RUN.

Форма плана процесса теперь использует тот же каталог доступных полномочий
этапа и тот же Markdown-редактор шаблона для назначения и ожидаемого результата,
что штатный редактор. При смене сотрудника ранее выбранные полномочия этапа
сбрасываются, чтобы не переносить их на другого исполнителя. Для нового,
ещё не сохранённого процесса серверной цели предпросмотра и автодополнения
переменных пока нет; форма не выдаёт локальный текст за проверенный шаблон.
Адресные frontend unit (3 теста), typecheck, ESLint и build — PASS на
незакоммиченном diff после `deb58752`; build предупреждает о чанке >500 KiB.
SHA исходника на host и в Pod совпал, Vite отдаёт изменённый модуль HTTP 200,
Deployment PWA Ready 1/1; визуальная проверка — NOT RUN.

Поля профиля сотрудника (имя, назначение, роль) вынесены в общий компонент для
ручной страницы и `UPDATE_AGENT` в плане помощника. Применение плана закрыто
до заполнения полей в лимитах штатной формы. Это только изменение профиля:
инструкции, runtime и полномочия имеют отдельные версии и команды, поэтому
их нельзя молча менять этим переходом. Адресные frontend unit (16 тестов),
typecheck, ESLint и build — PASS на незакоммиченном diff после `ae63c036`;

Карточка созданного или изменённого процесса теперь открывает штатную страницу
редактора в соседней панели открытого чата (`assistantForm=1`) после точного
readback, по тому же принципу, что образ и окружение. Маршрут больше не закрывает
диалог помощника. Это даёт владельцу штатные поля этапов, каталог прав,
валидацию и публикацию черновика без потери переписки. Адресные frontend unit
(20 тестов), typecheck, ESLint и build — PASS на незакоммиченном diff после
`a5e171f8`; build предупреждает о чанке >500 KiB. SHA страницы совпал на host
и в Pod, Vite отдаёт модуль HTTP 200, Deployment PWA Ready 1/1;
визуальная проверка — NOT RUN.

После создания IntegrationConnection карточка теперь открывает защищённый ввод
credential поверх сохранённого чата, а не уводит на глобальную страницу.
Поле значения вынесено из ручной формы в общий компонент и не входит в план,
историю или модель. Перед однократной отправкой форма перечитывает точный
Connection и Definition, сверяет возможность действия, версию и ключ
definition; после неопределённой ошибки автоматический повтор с новым ключом
не выполняется. Карточка перечитывает состояние после успешной настройки.
Адресные frontend unit (24 теста), typecheck, ESLint и build — PASS на
незакоммиченном diff после `822e42b2`; build предупреждает о чанке >500 KiB.
SHA защищённой формы совпал на host и в Pod, Vite отдаёт модуль HTTP 200,
Deployment PWA Ready 1/1; визуальная проверка — NOT RUN.

Карточка созданного сотрудника оставляет чат открытым и показывает штатную
страницу сотрудника в соседней панели: профиль, инструкции, runtime,
окружение и доступы доступны для дальнейшей ручной настройки. Карточка проекта
тоже сохраняет открытое окно и показывает обзор нового проекта рядом с ним;
после явного перехода по кнопке контекст меняется на Project, где начинается
проектный диалог. Старую организационную беседу и её полномочия нельзя
незаметно перенести между контекстами. Это не реализация предложенного моделью
изменения инструкций сотрудника: публикация остаётся отдельным owner gate.
Адресные frontend unit (23 теста), typecheck, ESLint и build — PASS на
незакоммиченном diff после `8ae256f9`; build предупреждает о чанке >500 KiB.
SHA страницы проекта совпал на host и в Pod, Vite отдаёт модуль HTTP 200,
Deployment PWA Ready 1/1; визуальная проверка — NOT RUN.

После плана автоматизации и привязки окружения к сотруднику карточки тоже
открывают соответствующие штатные экраны в соседней панели, сохраняя чат и
точный Project context. Предложенная помощником конфигурация проходит через
прежний план/owner command; экран остаётся доступен для проверки и дальнейшей
ручной настройки. Адресные frontend unit (23 теста), typecheck, ESLint и
build — PASS на незакоммиченном diff после `6d8f0a7c`; build предупреждает
о чанке >500 KiB. SHA страницы автоматизаций совпал на host и в Pod, Vite
отдаёт модуль HTTP 200, Deployment PWA Ready 1/1; визуальная проверка —
NOT RUN.

До отмашки ещё нужен аудит всей цепочки на текущем дереве: какие операции уже
используют штатные поля до подтверждения, а какие только открывают ручной экран
после создания черновика. Отдельно проверить публикацию окружения, изменение
его инструментов и политики, возврат после fresh-auth, переходы контекста и
восстановление долгих операций. Не выдавать открытие экрана после применения
за предпросмотр полной формы и не подтверждать изменение за владельца.

Решение владельца от 2026-09-25 задаёт единый UX для всех планов создания и
изменения: полная история диалога остаётся главным экраном, ответ помощника
содержит карточку подготовленного варианта, а кнопка карточки открывает большую
штатную форму поверх чата. Форма не подменяет и не закрывает диалог. Просьба
«переработай» создаёт новый независимый вариант; прежний вариант сохраняется,
не отклоняется и не объявляется устаревшим. Владелец может открыть, отредактировать
и применить любой сохранённый вариант, если его авторитетные версии ещё
совместимы с текущим состоянием. Применение одного варианта не обходит обычные
OCC, validation и owner gates другого варианта.

Незакоммиченный пакет после `3ebb1a0f` реализует этот контракт в проекции
разговора, store, форме и системном prompt `v33`. Control-plane возвращает все
планы разговора, а новый user turn больше не переводит предыдущий план в
`STALE`. Карточки вариантов вставляются сразу после соответствующего ответа
помощника по серверным timestamp, а не общей группой в конце истории. В UI
показан номер варианта и действие «Просмотреть и изменить»; формы плана и
штатные формы сущностей открываются модальным слоем поверх сохранённого DOM
чата. Результат после изменения проекта, сотрудника и IntegrationConnection
получил тот же точный readback и переход в штатную форму, что после создания.

В живом Chrome после hard reload найден и исправлен отдельный дефект пустого
чата: безусловный корневой `<template>` оставался реальным скрытым DOM-узлом и
давал журналу размер `0×0`. После замены на layout-контейнер журнал имеет размер
`1484×544`, три turn видимы, карточка `Вариант 1` стоит после ответа и открывает
форму `1690×950` поверх чата `1766×994`; фон имеет `inert` и `aria-hidden`.
Console errors/warnings — отсутствуют, наблюдавшиеся API-запросы — HTTP 200,
кроме ожидаемых abort при reload и одного клиентского `ERR_NETWORK_CHANGED` без
HTTP-ответа. Screenshot: `/tmp/kodex-plan-variant-overlay-v33.png`. Адресные Go
test, 105 frontend unit и typecheck — PASS на незакоммиченном дереве. Реальный
диалог с двумя сгенерированными вариантами — NOT RUN: он остаётся сценарием
ручной приёмки, чтобы не расходовать provider-вызов только ради синтетической
проверки.

Тот же аудит нашёл транспортный пробел: реализованные сервером и формами
`CREATE_INSTRUCTION_DRAFT`, `UPDATE_INTEGRATION_CONNECTION`, `UPDATE_WORKFLOW`
и `UPDATE_SCHEDULE` отсутствовали в Proto enum runtime → control-plane. Им
назначены новые непереиспользуемые номера `20..23`, generated Go обновлён
точными локальными plugin `protoc-gen-go v1.36.11` и

`make gen-proto` и `make check-proto-codegen` через удалённые Buf plugins —
NOT RUN/недоступны: registry вернул `403 Forbidden`; это не объявляется
успешной удалённой проверкой. Air увидел generated source, пересобрал
control-plane и восстановил readiness без application image rebuild.
