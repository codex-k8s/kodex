# SLO и управление ресурсами

## Начальные целевые показатели

Значения являются стартовыми и уточняются после измерений:

- доступность промышленных API управления и взаимодействия: 99,9% за месяц;
- подтверждение принятого Mattermost сообщения: p95 до 2 секунд без учета запуска агента;
- долговечная очередь: отсутствие потери принятого хода при одиночном перезапуске или отказе сервиса без локального состояния;
- повторный экземпляр расписания: 0 для одного `(schedule_id, scheduled_for)`;
- RPO резервного копирования: не более 15 минут для WAL PostgreSQL;
- RTO восстановления платформы: до 4 часов для документированной поддерживаемой топологии;
- исправление зависшей активной сессии: обнаружение не позднее двух интервалов сверки.

Задержка и доступность поставщика ИИ измеряются отдельно и не включаются в доступность платформы, но ошибка должна быть классифицирована и показана пользователю.

## Классы ресурсов

Агент или роль выбирает версионируемый `ResourceClass` с запросами CPU, памяти и временного хранилища, необязательным лимитом памяти и характеристиками нагрузки. Произвольные значения доступны только администратору.

## Admission

Перед созданием pod контроллер среды выполнения проверяет:

- доступные ресурсы и давление на узел;
- квоты namespace;
- ожидающие рабочие нагрузки;
- запросы класса ресурсов;
- максимальную параллельность организации и учетной записи;
- доступные простаивающие pod для вытеснения.

При нехватке ресурсов ход остается в очереди. Необратимая ошибка создается только после тайм-аута политики либо неустранимой ошибки проверки.

## Warm pods

- максимум один pod на сессию;
- TTL по умолчанию — четыре часа;
- вытеснение LRU применяется только к простаивающим сессиям без хода в очереди или выполнении;
- архив сессии и метаданные PVC не удаляются при вытеснении;
- количество прогретых pod и зарезервированные ресурсы наблюдаемы.

## Давление на хранилище

- Использование PVC и число кандидатов на очистку измеряются по рабочей области, сессии и классу хранилища.
- При нехватке ресурсов сначала удаляется самый старый прогретый pod без активной работы.
- PVC удаляется только после минимальной отсрочки и проверенного архива согласно `docs/operations/runtime-retention.md`.
- При достижении критического порога без подходящих PVC новые сессии остаются в очереди, а владелец получает предупреждение; непроверенные данные автоматически не удаляются.

## Limits

Лимиты CPU для запусков и сборок агентов не обязательны и применяются только по измеренной причине. Запросы и лимиты памяти и резерв узла должны предотвращать OOM хоста. Промышленные значения определяются нагрузочными тестами, а не размером текущего сервера.
