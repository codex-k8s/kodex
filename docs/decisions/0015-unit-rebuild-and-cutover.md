# ADR-MC-015. Полные unit и контролируемый cutover legacy

## Контекст

Развитие функциональности внутри большого `bot-service` создало связанные PR,
дорогие циклы review и архитектуру, которая не соответствует целевому
production-профилю. Платформа уже используется для dogfooding, поэтому
одномоментно выключить legacy нельзя, но продолжать строить новые сервисы как
внутренние пакеты монолита также нельзя.

## Решение

1. Каждый целевой service, gateway, job и PWA реализуется заново как полный
   самостоятельно поставляемый unit по `GUIDE-DOC-004`.
2. Legacy `bot-service`, runner, Control Center и contracts замораживаются и
   не используются как эталон нового кода.
3. Новые unit не реализуют постоянный compatibility facade и не выполняют
   dual write в legacy schema.
4. До cutover legacy продолжает обслуживать dogfooding. Допустимы только
   критические эксплуатационные исправления с отдельным owner gate.
5. После готовности unit выполняются backup, dry-run, one-shot forward
   migration, staging acceptance и переключение.
6. Rollback возвращает трафик и данные к проверенной резервной точке в пределах
   заранее установленного окна; после его закрытия legacy удаляется отдельной
   задачей.

## Последствия

- до cutover временно существуют два набора deployables, но только один
  authoritative runtime обслуживает пользователя;
- миграция данных и переключение становятся отдельными проверяемыми
  результатами;
- нет стоимости постоянной обратной совместимости с внутренней архитектурой,
  которую решено заменить;
- новые unit можно независимо проверять и принимать владельцем.
