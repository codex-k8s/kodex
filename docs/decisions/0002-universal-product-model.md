# ADR-MC-002. Универсальная продуктовая модель

## Решение

Домен строится вокруг `Organization`, `Workspace`, `Room`, `RoleDefinition` и `Agent`. GitHub и репозитории являются необязательной интеграцией. Одна организация на установку — первый профиль развертывания, но область организации присутствует в схеме и контрактах с начала миграции.

Соответствия Mattermost:

- `Workspace` = команда;
- `Room` = канал;
- `Conversation` = обсуждение либо привязка запуска без чата;
- `Agent` = отдельная учетная запись бота.

`Project`, `Chat` и текущая `AgentRole` поддерживаются как переходные имена интерфейса для ИТ-варианта.

В период расширяющей миграции `Workspace`, `Room`, `RoleDefinition`, `Agent`, `AgentAssignment`, `InstructionSet` и `InstructionVersion` получают собственные внутренние идентификаторы и обязательный `organization_scope` одной установки. Полные `Organization`, `Subject`, `Membership`, права доступа, квоты и admission в этот переходный срез не входят.

`Project`, `Chat` и `AgentRole` остаются совместимыми проекциями с отображением 1:1 на `Workspace`, `Room` и конкретный `Agent`. Один доменный владелец атомарно обновляет целевой агрегат и legacy-проекцию. Существующие API, callback ID, ключи сессий и чтение среды выполнения сохраняются до отдельного contract-изменения.

GitHub account и repository необязательны. Объект с `managed_by=git` доступен интерфейсу только для чтения до явного отсоединения от Git. Отсоединение сохраняет происхождение, повышает ревизию записи и создаёт событие аудита.

Первый сценарий без Git использует один ограниченный 65 536 UTF-8 байт неизменяемый Markdown в PostgreSQL. Текущий Mattermost-диалог `/agents` ограничен 3000 UTF-8 байтами, чтобы сохранённая инструкция гарантированно проходила байтовую проверку `textarea.Default` при повторном открытии; отдельная upload/API поверхность этим решением не вводится. Каждая публикация создаёт новую `InstructionVersion` с SHA-256 и ссылкой на инициатора; изменение или удаление версии запрещено. Это переходное хранение не меняет целевое решение `ArtifactVersion` и S3 из ADR-MC-006.

## Последствия

- Рабочая область вне ИТ работает без репозитория.
- Определение роли переиспользуется; агент хранит конкретные привязки учетной записи и конфигурации.
- Требуется поэтапная миграция данных и совместимый интерфейс.
- Термины конкретного поставщика не используются в универсальных сущностях.
- Одновременные legacy-only и dual-write процессы записи конфигурации запрещены: переключение требует короткого quiesce.
- Откат приложения выполняется без `Down`: N-1 читает сохранённую legacy-проекцию, а редактирование универсальной модели блокируется до исправления вперёд.
