# ADR-MC-011. Настраиваемые политики координации и внимания инициатора

## Контекст

Имена `director`, `manager`, `developer` и аналогичные отражают только один способ организации работы. Kodex должен поддерживать разработку ПО, продажи, бухгалтерию, документооборот и другие процессы без изменений кода. Промпты сами по себе не обеспечивают допустимые направления запуска, обратного вызова и уведомления человека.

## Решение

Полномочия задаются опубликованной версией Workflow и текущими grants агента:

- capability определяет доступное роли действие;
- allowlist и step keys WorkflowVersion разрешают координатору запуск точного
  целевого агента;
- Run фиксирует применённую WorkflowVersion и immutable RuntimeRevision;
- lineage неизменно хранит корневого человеческого инициатора и цепочку запусков;
- Human Gate задаётся опубликованной WorkflowVersion и открывается только
  owner-транзакцией после успешного шага.

Отображаемое имя и описание роли не участвуют в авторизации. Прямой запуск
человеком и делегирование являются разными специализированными командами;
делегирование наследует root actor и проверяет parent attempt, capability,
Workflow allowlist, step key и лимиты.

Рабочая роль возвращает результат координатору через server-owned callback
edge ровно один раз. Платформа требует действие человека только при открытом
Human Gate; проверка выполняется в доменном сервисе до создания делегирования,
callback либо gate continuation.

## Последствия

- Любой бизнес может именовать и связывать роли без изменения кода.
- Промпты объясняют политику, но не являются границей авторизации.
- Уже запущенный процесс сохраняет pinned WorkflowVersion и RuntimeRevision.
- Prompt и display role name не расширяют граф разрешённых делегирований.
