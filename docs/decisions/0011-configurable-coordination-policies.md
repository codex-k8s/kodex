# ADR-MC-011. Настраиваемые политики координации и внимания инициатора

## Контекст

Имена `director`, `manager`, `developer` и аналогичные отражают только один способ организации работы. MatterCodex должен поддерживать разработку ПО, продажи, бухгалтерию, документооборот и другие процессы без изменений кода. Промпты сами по себе не обеспечивают допустимые направления запуска, обратного вызова и уведомления человека.

## Решение

Полномочия задаются версионируемой политикой проекта:

- capability определяет доступное роли действие;
- relationship rule разрешает действие исходной роли над целевой ролью;
- process run фиксирует примененную ревизию политики;
- lineage неизменно хранит корневого человеческого инициатора и цепочку запусков;
- право привлечь внимание инициатора задается отдельной политикой и уровнем серьезности.

Отображаемое имя и `role_type` не участвуют в авторизации. Поставляемые профили верхнеуровневого координатора, координатора волны и рабочих ролей являются редактируемыми пресетами. Прямой запуск человеком координатора волны допустим политикой проекта; такой координатор возвращает шлюзы непосредственно корневому инициатору.

Обычное успешное завершение не упоминает инициатора. Рабочая роль возвращает результат разрешенному координатору. Платформа обращается к корневому инициатору только после окончательной ошибки либо при открытом ручном шлюзе. Проверка выполняется в доменном сервисе до создания делегирования или обратного вызова.

## Последствия

- Любой бизнес может именовать и связывать роли без изменения кода.
- Промпты объясняют политику, но не являются границей авторизации.
- Старые процессы сохраняют исходную ревизию, новые используют актуальную.
- Служебное `fyi: task complete` и обязательное упоминание владельца дочерними ролями удаляются.
