# ADR-MC-012. Локальная память проекта и ролей

## Контекст

Параллельные сессии должны переиспользовать подтверждённый опыт, не полагаясь
на историю одной Session. Передача проектных данных внешнему embedding API
создаёт нежелательную зависимость, стоимость и дополнительную границу доверия.

## Решение

Каноническая память хранится в PostgreSQL как версионируемые записи с происхождением, областью, важностью и состоянием. Области первой версии: весь проект и конкретная роль. Полнотекстовый поиск обязателен и работает без модели. `pgvector` является перестраиваемой поисковой проекцией.

Embeddings вычисляются только локальным runtime внутри управляемого кластера. Модель, размерность и checksum фиксируются в ревизии индекса; веса хранятся на управляемом томе. Ядро использует интерфейс embedding runtime и продолжает полнотекстовую работу при его недоступности. Внешние embedding API не входят в поддерживаемый путь.

Общепроектную запись публикует роль с соответствующей capability. Роль без такого полномочия сохраняет опыт только в собственной области и передает предложение разрешенному координатору через callback. Замена выполняется новой версией с `supersedes`; физическое удаление не используется как обычное редактирование.

Память является недоверенным историческим контекстом и не переопределяет системные инструкции, активный пользовательский запрос, `AGENTS.md` и политики платформы.

## Последствия

- Проектные данные не покидают управляемую инфраструктуру ради embeddings.
- Векторный индекс можно полностью перестроить после смены модели.
- История решений остается проверяемой и не превращается в скрытый промпт.
- Координация активной работы не строится на вероятностном поиске памяти.
