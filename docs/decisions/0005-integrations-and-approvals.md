# ADR-MC-005. Режимы интеграций и согласования

## Решение

Поддерживаются два явных режима:

- прямой инструмент или env среды выполнения для доверенных возможностей без гарантированной ручной приемки;
- управляемый шлюз MCP для контролируемых и опасных действий.

В управляемом режиме учетные данные остаются в шлюзе. Возможность имеет права, ограничения, класс риска, политику согласования и контракт идемпотентности. Агент запускает других агентов только через платформенный MCP, а упоминания из сообщений ботов не являются сигналом запуска.

Каждая разрешенная привязка MCP материализуется в Codex `config.toml` перед каждым `exec` или `resume` с максимальным допустимым `tool_timeout_sec`. Для ожидания согласования дольше одного хода используется не открытый вызов инструмента, а долговечное продолжение: квитанция `pending`, архив сессии, сохраненное решение и выполнение и новый ход продолжения с `resume` той же сессии.

## Последствия

- Определения YAML-MCP можно переиспользовать как пакеты интеграций.
- Нельзя выдавать прямые учетные данные и одновременно обещать обязательное согласование того же изменения.
- Шлюз интеграций становится границей безопасности и требует отдельной модели угроз.
- Согласование может пережить TTL pod, перезапуск шлюза и несколько суток ожидания человека.
