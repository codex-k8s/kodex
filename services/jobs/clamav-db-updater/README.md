# Обновление базы ClamAV

Самостоятельная фоновая задача обновляет подписанную базу сигнатур в общем
томе `clamav-database`. Исполняемый код — закреплённый официальный `freshclam`;
репозиторий владеет его конфигурацией и CronJob в
`deploy/k8s/base/clamav-db-updater/`. Сканер Control Plane монтирует этот том
только для чтения, остаётся без сетевого доступа и перечитывает базу через
`SelfCheck`. Успех Job сам по себе не подтверждает готовность сканирования:
авторитетный путь — `VERSION` рабочего `clamd` и проверка возраста базы.

Сетевой путь ограничен DNS и `clamav-egress-gateway:8080`; отдельный proxy
допускает только
`database.clamav.net:443` с проверкой CONNECT, SNI, TLS и DNS. При ошибке
загрузки сохраняется последняя целостная база. После семи суток без обновления
проверка навыков закрыто отклоняется. Секреты задаче не передаются.

## Сквозной сценарий и владение

| Граница | Контракт |
| --- | --- |
| Источник требования | Проверка и публикация навыков требуют актуального результата антивирусного сканирования. |
| Инициатор и полномочия | Kubernetes CronJob `clamav-db-updater` по расписанию; отдельный ServiceAccount без API-токена и RBAC. Пользовательский запрос не может запустить скачивание или выбрать адрес назначения. |
| Внешний endpoint | Только `https://database.clamav.net:443` через `clamav-egress-gateway:8080`; `freshclam` проверяет TLS и подпись базы. |
| Внутренний переход | Job обновляет файлы на PVC `clamav-database`; `clamd` перечитывает их через `SelfCheck`. Записи в доменный сервис, RPC и событие NATS отсутствуют. |
| Владелец данных и версия | Файлы базы ClamAV на PVC; точную загруженную версию показывает рабочий `clamd VERSION`, не статус Job. Повторное выполнение `freshclam` безопасно использует текущую версию; одновременное выполнение запрещено `concurrencyPolicy: Forbid`. |
| Ошибка и потребитель | Ошибка Job не удаляет последнюю целостную базу. Readiness сканера и проверка навыка отказывают закрыто, когда база отсутствует либо устарела; решение принимает Control Plane. |

Базовый манифест PVC требует хранилище с `ReadWriteMany` для независимых Pod
scanner и updater. Локальный одноузловой render меняет только режим PVC на
`ReadWriteOnce`; перенос этой подмены в многонодовый контур запрещён. Для
production нужен утверждённый RWX StorageClass и отдельный допуск владельца.
